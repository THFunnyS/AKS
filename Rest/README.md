# REST API - Управление покупателями и заказами

## Описание проекта
Проект представляет собой RESTful веб-сервис для работы с данными интернет-магазина.

В качестве основы использовано ранее разработанное приложение, содержащее две основные сущности:

Customer - покупатель;

Order - заказ.

REST API предоставляет возможность получать, создавать, изменять и удалять данные о покупателях и заказах.

Для обмена данными поддерживаются два формата: JSON и XML. Дополнительно реализованы XSL-преобразования, позволяющие отображать XML-ответы REST API в виде HTML-страниц непосредственно в браузере.
## Выбор технологии: JAX-RS или Spring REST
Для разработки приложения был выбран Spring REST.

JAX-RS - это спецификация Java, предназначенная для создания RESTful веб-сервисов. Она определяет стандартный набор аннотаций и механизмов для обработки HTTP-запросов. Для её использования необходима соответствующая реализация, например Jersey или RESTEasy.

Spring REST основан на Spring MVC и предоставляет средства для разработки REST API с использованием аннотаций и механизмов Spring Framework.

Основные причины выбора Spring REST:

1. Предыдущая версия приложения была разработана с использованием Spring Boot, поэтому перенести уже имеющийся код было рациональным выбором.

2. Spring REST позволяет повторно использовать существующие сервисы, DTO и репозитории.

3. Аннотации Spring MVC (@RestController, @GetMapping, @PostMapping, @PutMapping, @DeleteMapping) делают реализацию REST API достаточно простой и понятной.

4. Spring Boot обеспечивает удобную интеграцию с Spring Data JPA и механизмами обработки JSON и XML.

5. Использование более знакомой и удобной технологии позволило быстрее приступить к реализации функциональных требований задания.

Таким образом, Spring REST был выбран исходя из имеющегося опыта разработки и удобства интеграции с предыдущим приложением.
## Реализация REST API
Для работы с данными реализованы два контроллера:

- CustomerRestController - управление покупателями.

- OrderRestController - управление заказами.

### Покупатели

Базовый адрес: `/api/customers`

| HTTP-метод | Endpoint | Описание |
| ---------- | ---------| -------- |
|GET|`/api/customers`|Получение списка покупателей|
|GET|`/api/customers/{id}`|Получение покупателя по ID|
|POST|`/api/customers`|Создание покупателя|
PUT|`/api/customers/{id}`| Обновление покупателя|
|DELETE|`/api/customers/{id}`|Удаление покупателя|

### Заказы

Базовый адрес: `/api/orders`

|HTTP-метод| Endpoint| Описание|
| ---------| --------| --------|
|GET|`/api/orders`|Получение списка заказов|
|GET|`/api/orders/{id}`|Получение заказа по ID|
|POST|`/api/orders`|Создание заказа|
|PUT|`/api/orders/{id}`|Обновление заказа|
|DELETE|`/api/orders/{id}`|Удаление заказа|

Для операций создания и обновления используется DTO, который отделяет данные REST API от сущностей базы данных.

Также предусмотрена обработка ошибок: например, при обращении к несуществующему объекту возвращается HTTP 404, а при попытке удалить покупателя, у которого имеются заказы, возвращается HTTP 409.
## Поддержка JSON и XML
REST API поддерживает оба формата обмена данными:

- JSON;

- XML.

Формат входящих данных определяется заголовком Content-Type, а формат ответа - заголовком Accept.

Для получения списка покупателей в JSON используется заголовок:

Accept: `application/json`

Для получения XML:

Accept: `application/xml`

Для создания и обновления объектов соответствующий формат указывается в Content-Type.

Поддержка форматов реализована средствами сериализации и десериализации Spring Boot и Jackson.
## XSL-преобразования
Для отображения XML-ответов в браузере разработаны XSL-файлы:

|Файл| Назначение|
|--- | --------- |
|customers.xsl|Отображение списка покупателей|
|customer.xsl|Отображение отдельного покупателя|
|orders.xsl|Отображение списка заказов|
|order.xsl|Отображение отдельного заказа|

Файлы размещены в статической части приложения:

`src/main/resources/static/xsl/`

XSL-преобразования формируют HTML-страницы с таблицами и карточками объектов. Также предусмотрена навигация между покупателями, заказами и их списками.
## Автоматическое подключение XSL
Для автоматического подключения соответствующего XSL-файла к XML-ответам реализован фильтр XslXmlFilter.

Фильтр перехватывает HTTP-ответы и проверяет их тип содержимого. Если ответ содержит XML, в его начало добавляется инструкция обработки:

`<?xml-stylesheet type="text/xsl" href="/xsl/customers.xsl"?>`

Выбор файла зависит от запрошенного REST endpoint.

Таким образом, при открытии XML-ответа в браузере он автоматически преобразуется в HTML с помощью соответствующего XSL-файла.

JSON-ответы при этом не изменяются.

## Структура проекта

Основные компоненты приложения:

- model - сущности базы данных;

- repository - репозитории для доступа к данным;

- service - бизнес-логика приложения;

- dto - объекты передачи данных;

- api - REST-контроллеры и фильтр обработки XML-ответов;

- resources/static/xsl - XSL-файлы для преобразования XML в HTML.
## Запуск приложения

Для запуска проекта необходимо:

1. Установить JDK 17 или совместимую версию.

2. Установить и запустить PostgreSQL.

3. Настроить подключение к базе данных в application.properties.

4. Собрать и запустить Spring Boot приложение.

Запуск через Maven:

`mvn spring-boot:run`

После запуска REST API доступен по адресу:

http://localhost:8080/api/
